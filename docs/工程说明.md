# OpenHarmony 自动化工程说明

## 1. 工程概述

该工程集中管理 OpenHarmony 日常开发使用的 WSL 和 Windows 自动化工具。不同版本目录只保留一个轻量入口，公共逻辑统一放在：

```text
/home/shjb/work/Project/jiaoben
```

工程覆盖以下工作：

- OpenHarmony 代码拉取、同步和预编译下载；
- ArkUI-X 代码拉取、Android 编译和 VS Code 配置；
- rk3568 镜像、OpenHarmony SDK、TDD 和 XTS 编译；
- 镜像、SDK、测试产物复制到 Windows；
- RKDevTool 自动刷机和 HDC 设备操作；
- TDD、XTS 自动运行及报告定位；
- clangd 编译数据库、索引目录和 VS Code 配置；
- ccache、增量构建和当前 master 构建兼容修复；
- SO/ABC 替换、预览器替换和崩溃地址解析；
- WSL 文件缓存回收和 Windows 风扇控制；
- Windows 流水线压缩包解压、部署和验证。

它不是 OpenHarmony 源码的一部分，也不保存具体版本源码。具体源码仍放在各版本目录的 `code` 中。

## 2. 整体结构

工程分为四层：

```text
版本入口
  /home/shjb/work/1109/down.sh
        ↓
公共调度
  /home/shjb/work/Project/jiaoben/down-common.sh
        ↓
  ┌─────┴──────────────────┐
  ↓                        ↓
WSL 工具                 Windows 工具
  tools/                   D:\Project\jiaoben
  Python、Shell            BAT、EXE
  ↓                        ↓
修改 code 构建规则        复制、解压、刷机、运行测试
```

### 2.1 版本入口层

每个版本目录中的 `down.sh` 只做两件事：

1. 将自身所在目录保存为 `OPENHARMONY_WORK_PATH`；
2. 把原始命令参数交给公共 `down-common.sh`。

因此 `1030`、`1109` 等版本可以共用一套公共实现。

### 2.2 公共调度层

`down-common.sh` 是工程主入口，负责：

- 解析 `-image`、`-sdk`、`-tdd` 等命令；
- 组合 OpenHarmony 编译参数；
- 调用 `tools/` 中的补丁工具；
- 在 WSL 和 Windows 路径之间转换；
- 调用 Windows BAT 和 EXE；
- 记录命令、时间和返回状态到 `down.log`。

### 2.3 WSL 工具层

`tools/` 主要包含：

| 类型 | 作用 |
|---|---|
| `patch_*.py` | 修改刚拉取的 OpenHarmony 构建规则 |
| `patch_utils.py` | 提供统一校验、原子写入和日志函数 |
| `update_clangd_compile_commands.py` | 精简并稳定 clangd 编译数据库 |
| `clangd-config.yaml` | clangd 索引规则模板 |
| `vscode-settings.json.in` | OpenHarmony 和 ArkUI-X 共用的 VS Code 配置模板 |
| `wsl-memory-reclaim*` | WSL 空闲时回收文件缓存 |

### 2.4 Windows 工具层

Windows 工具负责 WSL 不适合直接完成的操作：

| 类型 | 作用 |
|---|---|
| `copy-*.bat` | 使用 Robocopy 复制或替换产物 |
| `extract-package.bat` | 使用 7-Zip 解压流水线产物 |
| `run-tdd.bat`、`run-xts.bat` | 调用 Windows 测试框架 |
| `replace-*.bat` | 替换预览器或 rk3568 产物 |
| `rkdevtool-control.exe` | 控制 RKDevTool 自动刷机 |
| `fan-control.exe` | 临时提高风扇转速并自动恢复 |

仓库中的 `windows/` 是备份，实际运行文件位于 `D:\Project\jiaoben`。

```text
code 中的源码

    ↓ RKDevTool、HDC、TDD/XTS 框架
```

主要外部依赖：

| 依赖 | 当前路径或要求 |
|---|---|

| TDD 框架 | `D:\rk3568\TDD\developer_test` |
| XTS 框架 | `D:\rk3568\XTS\dynamic` 和 `static` |
| SDK 目录 | `D:\Path\SDK` |

## 6. `down.sh` 完整用法

### 6.1 拉取、继续和更新

#### 重新拉取完整代码

```text
./down.sh -p [flash]
./down.sh --pull [flash]
```

```bash
./down.sh -p
./down.sh -p flash
```

该流程会删除当前 `code`，重新拉取代码和 Git LFS，下载预编译，配置开发环境，然后编译镜像、Windows SDK、`bundle_tool_test` 和 `bundle_framework_test`。镜像和 SDK 名称追加 `base`。

#### 从编译阶段继续

```text
./down.sh -c [flash]
./down.sh --continue [flash]
```

```bash
./down.sh -c
./down.sh -c flash
```

适用于代码、预编译和开发环境已经准备完成的情况，不重新拉取代码。

#### 更新现有代码

```text
./down.sh -u [flash]
./down.sh --update [flash]
```

```bash
./down.sh -u
./down.sh -u flash
```

该流程保存各子仓修改，通过 `repo sync -c -d` 回到 manifest 指定版本，同步代码和预编译、重新配置开发环境并编译 rk3568。

#### 拉取并编译 ArkUI-X

```bash
./down.sh -arkuix
```

预编译先按上游原始逻辑下载一次；失败时才应用 ArkUI-X 下载兼容修复。上游下载正常时不会修改下载器源码。

该流程会删除当前 `code`，拉取 ArkUI-X master 代码和 Git LFS，下载 ArkUI-X 预编译，编译 Android 目标并生成 `out/arkui-x/compile_commands.json`，把 ArkUI-X 组件保存到 `D:\Path\ArkUI-X\26.1.0\<版本名>base`。工作目录名开头的 `arkui-x` 会被去掉，例如工作目录为 `arkui-x0904` 时，基线目录为 `D:\Path\ArkUI-X\26.1.0\0904base`；`licenses` 由 `D:\Path\ArkUI-X\licenses` 统一共用，DevEco 实际使用的组件位于 `D:\Path\ArkUI-X\26.1.0\arkui-x`。同步、Git LFS 和预编译下载失败时最多重试三次。

只编译当前代码并替换实际使用的 ArkUI-X Windows SDK：

```bash
./down.sh -buildArkuiX
./down.sh -buildArkuiX save
./down.sh -buildArkuiX fast
./down.sh -buildArkuiX fast save
```

默认在编译成功后替换 `D:\Path\ArkUI-X\26.1.0\arkui-x`。传入 `save` 时不替换默认 SDK，而是去掉工作目录名开头的 `arkui-x` 后新建目录；例如 `arkui-x0904` 会保存到 `D:\Path\ArkUI-X\26.1.0\0904`。传入 `fast` 时追加 `--fast-rebuild`，可与 `save` 同时使用。日常编译不会重复生成 `compile_commands.json`；只有重新拉取流程会显式传入 `--export-compile-commands`。

不编译，直接使用已有构建产物替换 Windows SDK：

```bash
./down.sh -copyArkuiX
```

### 6.2 PR 和本地修改验证

#### 应用一个 GitCode PR

```text
./down.sh -pr <GitCode PR 地址>
```

```bash
./down.sh -pr https://gitcode.com/openharmony/bundlemanager_bundle_framework/pull/12346
```

PR Diff 会被应用并暂存；工作区原有修改不会加入暂存区，不会创建提交。

#### 编译验证当前修改

```text
./down.sh -build [flash]
```

```bash
./down.sh -build
./down.sh -build flash
```

用于 base 已经成功，之后又应用 PR 或修改源码的情况。编译 image、SDK、`bundle_tool_test` 和 `bundle_framework_test`。

### 6.3 开发环境配置

#### clangd

```bash
./down.sh -clangd
```

单独安装或刷新 clangd 索引配置、VS Code 配置和 GN 编译数据库更新规则。

#### 独立 Git 仓库格式化配置

```bash
./down.sh -testVscode
```

遍历 `/home/shjb/work/test/*/.git`，使用统一模板完整覆盖各仓库的 `.vscode/settings.json`，并将该文件加入仓库本地忽略。格式化程序和规则都直接使用 `tools/` 中的固定文件。

#### ohpm

```bash
./down.sh -ohpm
```

单独注释 `build.sh` 中 ohpm 初始化失败退出代码。

#### 构建兼容修复

```text
./down.sh -fix
./down.sh -fix image
./down.sh -fix sdk
./down.sh -fix image sdk
./down.sh -fix tdd <编译目标>
./down.sh -fix arkuix
```

```bash
./down.sh -fix
./down.sh -fix image
./down.sh -fix sdk
./down.sh -fix image sdk
./down.sh -fix tdd ace_engine_test
./down.sh -fix tdd bundle_tool_test
./down.sh -fix tdd bundle_framework_test
./down.sh -fix arkuix
```

不传参数时同时应用 image 和 SDK 修复。`arkuix` 修复预编译下载请求头、HTTP 重试和线程错误返回。`--remove image|sdk` 和 `--remove tdd <目标>` 由完整流程内部使用，日常不需要手动调用。

### 6.4 镜像

#### 编译镜像

```text
./down.sh -image [clangd] [fast] [flash] [cachelog]
```

| 参数 | 作用 |
|---|---|
| `clangd` | 生成并更新 `compile_commands.json` |
| `fast` | 使用 `--fast-rebuild` |
| `flash` | 编译、复制成功后刷机 |
| `cachelog` | 本次编译开启 ccache 详细日志 |

```bash
./down.sh -image
./down.sh -image fast
./down.sh -image clangd
./down.sh -image clangd fast
./down.sh -image cachelog
./down.sh -image fast cachelog
./down.sh -image clangd fast cachelog
./down.sh -image flash
./down.sh -image fast flash
./down.sh -image clangd fast flash cachelog
```

#### 单独复制镜像

```text
./down.sh -copyImage [base] [copy|flash] [device=<connect-key>]
```

| 参数 | 作用 |
|---|---|
| `base` | 目录名和标记文件名追加 `base` |
| `copy` | 只复制，默认模式 |
| `flash` | 复制后刷机 |
| `device=<connect-key>` | 多个 HDC 设备时指定设备 |

```bash
./down.sh -copyImage
./down.sh -copyImage copy
./down.sh -copyImage base
./down.sh -copyImage base copy
./down.sh -copyImage flash
./down.sh -copyImage base flash
./down.sh -copyImage flash device=aaa
./down.sh -copyImage base flash device=aaa
```

默认目标是 `D:\rk3568\images<工作目录名>`，例如 `D:\rk3568\images1109`。

#### 单独使用 base 镜像补刷

```bash
./down.sh -flash
```

不重新编译或复制，直接使用 `images<工作目录名>base` 刷机，成功后运行 `ace_engine` 和 `bundle_framework` TDD。

### 6.5 SO 和地址解析

#### 单独替换 rk3568 ArkUI 产物

```bash
./down.sh -so
```

将当前 rk3568 的 ArkUI SO 和 ABC 推送到板子，然后重启设备。

#### 单独解析 SO 地址

```text
./down.sh -addr <SO 文件名> <地址> [地址 ...]
```

```bash
./down.sh -addr libarkui_navigator.z.so 0x4504
./down.sh -addr libarkui_navigator.z.so 0x4504 0x476c

```

SO 从 `out/rk3568/lib.unstripped` 中自动查找。


不传参数时编译完整 SDK 和完整 ArkTS，只生成 Windows SDK。

```bash
./down.sh -sdk

./down.sh -sdk cachelog

./down.sh -sdk 1.1 fast

./down.sh -sdk 1.1 full fast cachelog
```

#### 单独复制 SDK

```bash
./down.sh -copySdk
```

将现有 Windows SDK 压缩包复制并解压到 `D:\Path\SDK\<工作目录名>`。

#### 单独替换预览器

```bash

```

使用已编译的 SDK 预览器替换 `D:\Path\SDK\26.1.0\previewer\common\bin`。脚本会关闭 `Previewer.exe`，不会关闭 DevEco Studio。

### 6.7 TDD 配置与编译

#### 配置和更新 Windows TDD 环境

```bash
./down.sh -syncTdd
```

`-syncTdd` 将超时设置为 60 秒、配置 Windows 测试目录，再把当前源码中的 `developer_test` 和 `xdevice` 同步到 Windows，只保留历史报告。

#### 编译 TDD

```text
./down.sh -tdd [目标] [fast] [cachelog]
./down.sh -tdd [目标] [fast] [cachelog] run [测试类 [测试用例]]
./down.sh -tdd [目标] [fast] [cachelog] report [TDD 参数 ...]
```

- 不传目标时默认 `ace_engine_test`；
- `fast` 使用快速重编译；
- `cachelog` 开启本次 ccache 详细日志；
- `run` 只支持单个可执行测试套，不支持部件目标；
- `run` 后最多传测试类和测试用例两个参数；
- `report` 后的参数原样传给 TDD 框架。

```bash
./down.sh -tdd
./down.sh -tdd fast
./down.sh -tdd ace_engine_test
./down.sh -tdd bundle_tool_test
./down.sh -tdd bundle_framework_test
./down.sh -tdd bundle_framework_test fast
./down.sh -tdd select_test_ng
./down.sh -tdd select_test_ng fast
./down.sh -tdd select_test_ng run
./down.sh -tdd select_test_ng run SelectControlSizeNg
./down.sh -tdd select_test_ng run SelectControlSizeNg ResetShowInSubWindow001
./down.sh -tdd select_test_ng report
```

### 6.8 TDD 复制和运行

```text
./down.sh -copyTdd [部件名|测试套]
./down.sh -copyTdd <测试套> run [测试类 [测试用例]]
./down.sh -copyTdd [部件名|测试套] report [TDD 参数 ...] [tag=<标记>]
```

- 不传名称时默认 `ace_engine`；
- 部件支持复制和 `report`，不支持 `run`；
- 单个测试套支持复制、`run` 和 `report`；
- `tag=<标记>` 给报告目录追加标记；
- `report` 自动添加 `run -t UT -tp <部件>`；
- 单个测试套还会自动添加 `-ts <测试套>`。

`report` 支持的常用参数：

| 参数 | 作用 |
|---|---|
| `-tm <模块名>` | 只运行指定测试模块 |
| `-tc <类名.用例名>` | 指定用例，`类名.*` 表示整个类 |
| `-tl <0～4>` | 指定测试级别，多个级别用逗号分隔，不能和 `-tc` 同时使用 |
| `-iter <次数>` | 在一次任务中重复运行 gtest |
| `--repeat <次数>` | 重复执行整个 TDD 任务 |
| `-ra random` | 随机打乱测试顺序 |
| `-ta <键:值>` | 传递驱动参数，多个参数用分号分隔 |
| `-hlg` | 不在终端显示任务运行日志 |
| `-hg 0` | 不采集或显示设备 hilog |
| `-cov` | 执行覆盖率流程 |

```bash
./down.sh -copyTdd
./down.sh -copyTdd ace_engine
./down.sh -copyTdd bundle_framework
./down.sh -copyTdd select_test_ng
./down.sh -copyTdd select_test_ng run
./down.sh -copyTdd select_test_ng run SelectControlSizeNg
./down.sh -copyTdd select_test_ng run SelectControlSizeNg ResetShowInSubWindow001

./down.sh -copyTdd bundle_framework report
./down.sh -copyTdd select_test_ng report
./down.sh -copyTdd select_test_ng report -tc SelectControlSizeNg.ResetShowInSubWindow001
./down.sh -copyTdd select_test_ng report -tc "SelectControlSizeNg.*"
./down.sh -copyTdd select_test_ng report -tl 1,2
./down.sh -copyTdd select_test_ng report -iter 5
./down.sh -copyTdd select_test_ng report --repeat 5 -ra random
./down.sh -copyTdd select_test_ng report -hlg -hg 0
./down.sh -copyTdd bundle_framework report tag=1109base
```

## 13. 固定路径集中配置

| 当前日志 | `LOG_PATH=$OPENHARMONY_WORK_PATH/down.log` |

| Windows CMD/HDC | `WINDOW_CMD_PATH`、`WINDOW_HDC_PATH` |
| Windows BAT/EXE | `WINDOW_*_SCRIPT`、`WINDOW_RKDEVTOOL_CONTROL`、`WINDOW_FAN_CONTROL` |
| SDK/预览器 | `WINDOW_SDK_PATH`、`WINDOW_PREVIEWER_PATH` |
| 镜像 | `WINDOWS_IMAGE_PATH`、`WINDOWS_TEMP_IMAGE_PATH` |
